# TIME 平台重新执行计划

**目标：** 在 Mac 本机继续开发，以 u20 为首个目标设备，完成用户额度、审批邮件和统一管理入口；保护已有训练任务。pro6000d 使用不同 Slurm 版本，单独适配。

**架构：** TIME 保留 Cockpit 入口、现有平台 API 和 Slurm；真实 GPU 资源分配前由 Slurm 控制器执行可信额度门控。邮件审批与申请记录共享同一状态和审计。未完成或未验证的功能默认关闭。

**技术：** Python、SQLite、Cockpit、Slurm 19.05.5、SMTP/TLS、Git；pro6000d 为不同版本的独立适配目标。

## 现状与约束

- `u20-slurm19` 的 `d577eca` 为计划起点。`u20-handoff-work/` 是本机未跟踪草稿，不代表已审查或完整交付；无效符号链接交付不得绕过。
- 每用户每月按 GPU 数量乘占用时间计费：debug 5、important 100、normal 500 GPU·小时，按次序消耗；最后额度耗尽后现有任务继续并记录超额，未启动任务继续排队且不能分配 GPU；同月追加先抵扣欠额。
- 每次变更明确列路径提交并推送对应目标分支；部署前提交并记录设备、提交、时间、备份、检查结果和回滚。禁止提交秘密、数据库、备份和运行日志。
- 不运行测试或模拟，允许语法、静态和部署健康检查；上线所需的并发、恢复和权限行为尚不能凭静态审查证明。不得声称严格门控已启用。不得干扰现有训练。
