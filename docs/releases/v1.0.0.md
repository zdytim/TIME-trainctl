# TIME Trainctl v1.0.0 候选发布说明

首版是对应 pro6000d 的 Slurm 26.05.5 部署的源码版本。升级依赖匹配的 Slurm 构建产物及已有环境。仓库同时保留 u20 的 Slurm 19 适配，其功能和上线状态以 [u20 部署记录](../../research/slurm19/u20-selectable-live-deployment-record.md) 为准。

## 面向训练者

- Cockpit 提供提交训练、队列和日志、GPU 监控、额度与申请入口。训练者可在网页和 `timectl` 查看账户额度。
- 提交时选择 `debug`、`important` 或 `normal` 月度档位。按实际占用 GPU 的时间结算。普通用户的待启动任务在所选档位余额不足时继续等待，运行中的任务可以完成并计入超额。
- 新提交的任务无需填写单次运行时限。异常退出的任务可由用户核对后重新提交。
- 追加本月 GPU 小时和调整长期资源上限使用不同的申请。追加时数计入当月 `normal` 档，长期上限控制 GPU 张数、并发和活动任务数。
- `timectl gpu` 支持终端表格和 JSON。两种格式均按账户的 GPU 张数显示。只读 MCP 和逐次终端确认的写操作入口见 [CLI 和 MCP 指南](../../pro6000d-cli-mcp/README.md)。

## 面向管理员

- 从「用户与额度」创建或开通训练账户。流程核对 Slurm 的 `training` 关联后加入训练组。已有账户保留登录密码。
- 最高优先级账户享有无限月度 GPU 小时。该用户的任务等待时，其他用户的待启动任务继续等待，已运行任务继续运行。
- pro6000d 的发布依据见 [月度计费和任务时限](../../deployment-records/2026-11-18-pro6000d-actual-usage-unlimited.md)、[严格优先级](../../deployment-records/2026-11-17-pro6000d-strict-priority-active.md)、[CLI 显示](../../deployment-records/2026-11-18-pro6000d-cli-display.md) 与 [账户开通](../../deployment-records/2026-11-18-pro6000d-account-enrollment.md)。

## 验收状态

- 2026 年 11 月 18 日已在 pro6000d 用已有普通训练账户完成登录、单卡训练、日志和扣费查询。Slurm 作业状态为 `COMPLETED`，退出码为 `0`，`debug` 档实际增加 6.8506 GPU 秒用量。
- 新增 Linux 账户并首次登录提交的完整流程仍需单独验收。
- 网页和 CLI 的卡数显示已核对。设备数据的后端访问边界仍待验收。
- 部分 Slurm 提交失败仍需要人工确认。恢复前应核实作业身份和账本预约，避免重复提交或扣费。
- 全新服务器的安装包及从空环境开始的安装流程仍需单独验收。

本候选版整理仓库和文档。保留安装器使用的 Cockpit 资源、构建补丁、验证代码与部署记录。已移除的预览副本和实验草稿可在候选分支的 Git 历史中查阅。当前服务的部署版本以各主机的记录为准。
