本目录为取回 u20 任务 attempt 6 后的独立审查副本，不代表已交付或已部署版本。

## 静态修正

- 账本重放 START_COMMIT 时从记录更新实际 GPU 数，不沿用请求数。
- 月额未启用及不请求 GPU 的 CPU 作业，不因零 GPU 把月额控制器置为不健康；GPU 数未知仍失败关闭。
- 时钟采样移到互斥锁内，防止并发线程以不同顺序采样、加锁造成虚假回拨。
- 状态目录或标记缺失且未要求启用时返回 disabled，不创建目录、账本或时钟文件。`SLURM_MONTHLY_QUOTA_REQUIRED=1` 时缺失、非法状态返回错误；标记及状态目录须可信，启用前必须由安装流程准备。**现有安装脚本没有完成这一配置联动，不能启用。**

此前字段数、北京时间月界、恢复对账、GPU actual TRES、优先级高位检测和时钟回拨检查已在 u20 的 19 补丁中出现，仍未经行为验证。

## 禁止上线的待解决问题

1. `_now_ns()` 每次读时写 clock.fence 且 fsync；调度预览、优先级循环在持锁路径中执行，可能造成严重阻塞。直接删除同步写入会失去重启后回拨检查，需要重新设计分配事务的持久化与恢复并验证。
2. 需要全面审计所有资源分配/释放/恢复路径、节点异步 epilog 及崩溃的一致性；现有 release 调用位置不构成已经验证的物理 GPU 释放时刻。
3. 真实运行主机 configure、依赖、插件、账户和 GPU TRES 必须逐项比对；隔离构建缺失 munge/PAM，绝不可投入运行。
4. 启用/安装工具必须为 `SLURM_MONTHLY_QUOTA_REQUIRED=1` 管理安全状态目录和 marker，保证重启、回退及丢失状态时不静默放行。
5. 本地修复更新了 C 和 patch，尚未重新生成原上游 FILE-MANIFEST 和报告；原始证据与新版本哈希不等同。
