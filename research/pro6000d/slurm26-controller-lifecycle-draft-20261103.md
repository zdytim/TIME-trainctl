# Slurm 26 candidate: experimental controller lifecycle

The disabled controller candidate defines ledger reconciliation and the root-broker control socket but had no controller lifecycle calls. `slurm26-controller-lifecycle-draft.patch` adds a guarded startup path after job restoration and before main scheduler initialization: acquire Slurm and TRES read locks, run the candidate reconciliation, and start the control service only after reconciliation succeeds. It also stops the control thread after scheduling stops, closes ledger state only on final shutdown, and preserves it across the controller's in-process reconfiguration loop. Both `TIME_ENABLE_MONTHLY_LIFECYCLE_DRAFT` and `TIME_ENABLE_MONTHLY_ALLOCATION_GUARD` must be explicitly defined for this draft code to compile into the controller; neither is enabled by this change.

This does not complete or enable the feature. The selector still deliberately aborts successful intents and queues GPU jobs, resource release is unproven, pre-opened witness descriptor handling and startup ordering require further work, and the reconciliation and control lifecycle have not been exercised. The independently reviewed controller and broker patches have further unresolved defects. The hook must not be activated or deployed in production. Existing training remains under the currently deployed ordinary Slurm behavior.

The patch applies with `git apply --unidiff-zero` after `slurm26-reservation-draft.patch`; its intended companion recovery change is `slurm26-recovery-fail-closed-draft.patch`. Only static inspection and reverse patch applicability were performed; no tests or production operations were run.
