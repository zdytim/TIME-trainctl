# Root-owned quota witness candidate

This staged candidate adds a separate append-only witness outside Slurm's service-owned state directory. A root launcher opens and locks an existing private root-owned witness before executing `slurmctld`; the descriptor survives the privilege drop. Each WAL event is acknowledged only after the WAL, checksum checkpoint and witness record have each been fsynced. On restart the controller requires the witness's last sequence and digest to match the local WAL/checkpoint and fails closed on missing, invalid, stale or inconsistent state. A fresh-only initializer refuses to replace existing state or initialize a nonempty WAL. These files are not installed, and quota enforcement stays disabled.

The root-owned witness protects against an ordinary restoration of only Slurm's service-owned ledger and checkpoint to a matching older pair. It is not an independent host or immutable storage: an administrator, a compromised controller holding its writable descriptor, or a whole-filesystem rollback can still alter or roll back all evidence. It does not resolve migration of prior usage, unsupported job shapes, crash ambiguity between three fsyncs, or the full power-loss and runtime security model. A crash between writes intentionally requires operator reconciliation and must not silently recreate state. The initializer only accepts an exactly empty ledger and is not evidence that historical usage may be reset. Before deployment, review process/descriptor inheritance, systemd integration, service-user trust, storage ordering, offline recovery and real workload safety.
