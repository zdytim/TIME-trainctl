# Initial monthly ledger provisioning candidate

`u20-training-platform/tools/time-quota-ledger-init.py` provisions only a genuinely new pair of U20MQ1 files. It requires an existing trusted state directory owned by the effective service user, rejects symlink or writable ancestor directories, and uses exclusive 0600 creation, file fsync and directory fsync. It never overwrites, truncates, repairs or removes an existing ledger. Partial initialization intentionally remains for review; the controller rejects incomplete pairs.

Run only under the intended slurmctld identity after independently confirming fresh accounting is appropriate, knowing the current Slurm job state, and reviewing activation/migration. The tool does not verify old usage, installed controller state, running jobs, file-system crash semantics or safely repair partial initialization. At the initial source review no invocation or behavioral tests had been performed; the controller gate stays disabled.

On 2026-10-30, committed fixture `6d5a95f` ran the initialization and offline inspection tools as UID/GID 64030 inside a networkless container with a private `/run` tmpfs and no host mounts or GPUs. It verified the explicit fresh-ledger acknowledgement, initial file contents and permissions, refusal to overwrite an existing pair, refusal to inspect a locked WAL, and rejection of a group/other-writable state directory and a symlink state directory. The first fixture run lacked the container capability needed to change a service-owned test directory's mode and did not complete; the successful run added only that capability in the isolated container. This is not a production initialization or evidence of historical usage migration, atomic power-loss recovery, or protection from coordinated rollback of WAL and checkpoint. The gate remains disabled.
