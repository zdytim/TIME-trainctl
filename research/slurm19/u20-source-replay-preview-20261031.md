# Controller-source replay in isolated recovery preview

On 2026-10-31, the `7a06cff` source was independently reconstructed on u20 from the pinned Slurm archive and committed patch stack. The resulting `monthly_quota.c` SHA-256 `9c3c42de457cfec0bf929db5e9c06c79893e422252f0f1eacf54fba6c2c932fb` matched the source from the candidate build. The `70fe951` helper builder extracted the source replay and required dependencies and built a read-only helper on u20; two builds at different paths produced SHA-256 `3970903d61231dcbd64e88341ec2157fcdedb4e38916d41dc4a3ee4726545dec`. Four source-level fixture cases passed on both Mac and u20: valid grant, valid allocation lifecycle, unmatched abort and duplicate grant. The extracted code substitutes allocation/string functions, is not the controller binary and does not reconcile real Slurm jobs.

The `22d1472` preview requires this exact root-owned helper to replay the copied WAL before producing a successful preview. Two networkless isolated running-job cases passed with image `time-semantic-recovery:7d18c83` (SHA-256 `92f986fb32d0a1e458c6af0cb22b497b77b21276b4885976bc31eadfec9a5ab4`): each used a real private broker SQLite, simulated marker lag, a staged controller and synthetic GPU job. After preview and container-only marker writing, the approval reconciled without double credit, usage increased and the job completed. One case was run with its immediate parent image before the additional negative fixture was added; the second and the negative case used the named image.

An independent negative fixture supplied a WAL whose marker history and approval rows matched structurally but whose earlier ABORT had no corresponding prepared job. The source replay rejected it, no successful preview manifest or candidate marker files were emitted, and the original fixture files remained unchanged. This demonstrates a failure that hashes alone would not catch; it is not exhaustive validation of all malformed WALs, full source-to-binary provenance, service lifecycle races or scheduler-state reconciliation. No production ledger, jobs or device nodes were mounted or altered.

The host queue was empty, Slurm and training backend active, `/dev/nvidia0` showed `other::---`, and `SlurmctldParameters` remained unset after the tests. The helper and preview are not installed for production and monthly enforcement remains disabled.
