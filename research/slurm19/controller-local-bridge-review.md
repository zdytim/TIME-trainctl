# Staged controller local bridge

`controller-local-bridge.patch` follows `bcc6177` and `3ccd0a9`. A primary controller with the quota feature enabled starts a bounded local Unix socket in its service-owned StateSaveLocation. The socket is mode 0600 and the server independently requires Linux SO_PEERCRED UID 0; the intended client is the existing root platform broker, which must authenticate the real user and authorize admin grants. `SNAP uid` reads the controller snapshot; `GRANT uid month gpu_seconds grant_id actor` returns success only after the controller primitive has durably recorded the grant and sequence checkpoint. Read and write parsing is bounded, client receive/send is timeout-limited, and stop joins the worker before the ledger is closed.

This is a candidate, not a deployed or verified interface. No broker client, user authorization, durable application-to-grant reconciliation, user-facing API, or MCP wiring exists yet. A lost or partial grant response is unknown and a retry must use identical grant ID and fields. Socket start failure leaves the quota ledger separate but makes the bridge unavailable. An existing socket path is never removed on startup, including after a crash; manual identity-checked cleanup is needed. Enabling the quota feature via live reconfiguration does not start the bridge until the next primary controller startup. The directory and slurm service user must be trusted; root access is privileged. Shutdown, locking, security, ABI and power-loss behavior have not been tested. Do not enable this candidate in production.

An initial isolated build of `b71dca2` linked successfully but warned about an ignored stop-pipe write. `controller-local-bridge-io-fix.patch` follows it, handles interrupted/failed wakeups, breaks on listener errors, and handles partial response writes. Incomplete client responses remain unknown. This is not behavior verification.
