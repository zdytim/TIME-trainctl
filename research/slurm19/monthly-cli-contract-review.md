# Staged monthly CLI contract

The incremental `u20-broker-monthly-capabilities.patch` follows the broker's monthly outbox patch and reports request idempotency and grant-reconciliation contracts. `available` requires explicit `monthly_controller.grant_enabled`; the monthly quota mode is still staged with enforcement_ready false. The CLI accepts monthly applications only if the discovered server advertises the exact idempotency contract and availability, and supplies a stable request ID, hours and Beijing month. Legacy non-idempotent application creation remains blocked. `request-status` can correlate an unknown monthly creation with an exact visible application body and reason; admin reconciliation invokes the dedicated broker endpoint using an explicit confirmation.

This is staged source, not a claim that the gate or grant service is active. A capable server can still be unavailable; the controller outcome and application status remain authoritative, and a 5xx after a mutation is unknown. The controller, broker patches and CLI have not been behavior-tested or deployed together. MCP mutations remain withheld.
