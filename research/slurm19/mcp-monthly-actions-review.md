# Staged MCP monthly applications and decisions

The candidate MCP exposes monthly application creation, application decisions, and grant reconciliation only when a host consent channel is present. Application creation requires the broker's explicit `owner-request-id-v1` capability and uses the same stable request ID in the application body and local request ledger. Grant reconciliation requires the advertised `application-grant-v1` capability and preserves the controller's original outbox fields. Decisions and reconciliation rely on the broker's existing authenticated admin check; a host confirmation cannot grant administrator privileges. The terminal host displays each exact normalized POST body and requires an explicit YES.

Old servers and absent capabilities do not enable monthly application creation. Temporary and permanent quota creation remain blocked for lack of a server idempotency contract. MCP is read-only without a trusted consent host. Monthly enforcement is not asserted. This is staged source: no prompts, mutations, tests, live service changes or task submissions were made. Approval, concurrent retry and failure semantics still need end-to-end validation before deployment.
