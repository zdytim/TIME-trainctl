# u20 controller and plugin linkage prerequisite

Read-only ELF inspection of the unified candidate built from `86352c3` on 2026-10-30 found that its `slurmctld` depends on `libslurmfull.so` and has RUNPATH `/home/u20/.local/share/time/builds/repro-slurm-86352c3/stage/lib/slurm`. The candidate controller references `gres_job_quota_gpu_shape`, which is exported by the candidate `src/api/.libs/libslurmfull.so` but absent from the installed `/usr/lib/x86_64-linux-gnu/slurm-wlm/libslurmfull.so`. The candidate backfill plugin also has an unresolved `monthly_quota_queue_current` reference expected from its matching controller.

Therefore copying only the controller or only the backfill plugin into the live installation is not a valid deployment plan. The compiled output's user-owned build path is also not a trusted runtime location for a root service. The candidate library SHA-256 is `4a017f53703e08da15ae69d4a08ed5b3cdba2025a6f1646f6585006bc638efe5`; the observed installed library SHA-256 is `e32129f4f522faf3db8d44a72e7074adb9a87abbd3906bfa0e58c8224552d1a1`. These are evidence at inspection time, not a compatibility guarantee.

Before deployment, design and review a root-owned, versioned controller/library/plugin bundle with its final paths and all required compatible plugins. Do not replace the system-wide library used by other Slurm processes without understanding their ABI and protecting active jobs. Confirm target-side dependency resolution and plugin loading in an isolated environment, and prepare exact component-level rollback; ELF symbol presence alone is insufficient. No loader, candidate process, test, system file or service was run or modified during this inspection.
