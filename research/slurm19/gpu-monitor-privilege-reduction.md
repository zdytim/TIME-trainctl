# GPU monitoring privilege reduction candidate

On u20, a root-run `nvidia-smi` was observed to chmod NVIDIA character devices to `0666`, defeating the device ACL's `other::---` restriction. This candidate changes the training backend's bounded XML probe to run through `/usr/bin/setpriv` as an explicitly configured non-root `gpu_probe_user`, with its primary group and no supplementary groups. A root-run backend without a valid non-root probe user fails closed for GPU monitoring rather than invoking the tool as root. Other backend functions remain independent. The u20 installer configures the designated non-root administrator as the probe user and preserves an existing explicit value.

On the current u20 host, a manual `setpriv` invocation as `u20`, with supplementary groups cleared, returned XML for the RTX 4090 and five process entries while leaving `other::---` on `/dev/nvidia0`. This was a bounded direct command, not an end-to-end test of the changed backend. The probe account must have the necessary device access independently; `gpu-acl.py` currently grants the administrator a named ACL. Root and GID restrictions do not stop other root-run tools or node recreation from changing permissions. This mitigation does not complete the system-wide anti-bypass requirement, and neither the driver settings nor the live backend configuration has been changed by this candidate.
