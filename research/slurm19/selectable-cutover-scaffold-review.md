# Selectable-tier cutover scaffold status

2026-11-02. `selectable-tier-cutover-scaffold.patch` is a candidate, not an active deployment. It stages V2 selected-tier identity, concurrent accounting and WAL replay, allocation admission, per-job queue ordering and a SNAP2 controller response. The broker candidate consumes SNAP2 only with a separate explicit selectable-cutover verification flag. Legacy snapshots are rejected in V2 mode. Ordinary builds refuse V2 replay and cutover: `TIME_ENABLE_SELECTABLE_V2` defaults to zero. The candidate includes a root-only, explicit reset command guarded by that compile-time flag, which refuses cutover while any job is active or queued. This experimental path is not yet verified or enabled and must not be presented as enforcing selectable tiers.

The scaffold has not been proven end to end. In particular, cutover and rollback, full crash recovery, scheduler and broker integration, authorization fencing, deployment procedure and operation against a real Linux Slurm instance remain to be reviewed and verified together. No active ledger should be rewritten and no running allocation interrupted to perform cutover. The candidate resets unclassified old consumption to zero, retaining previously approved grants and the old WAL for audit/rollback. It does not delete live records; actual cutover and any deletion still require the reviewed deployment procedure.
