# Selectable-tier cutover scaffold status

2026-11-02. `selectable-tier-cutover-scaffold.patch` is a candidate, not an active deployment. It stages V2 selected-tier identity, concurrent accounting and WAL replay, allocation admission, per-job queue ordering and a SNAP2 controller response. The broker candidate consumes SNAP2 only with a separate explicit selectable-cutover verification flag. Legacy snapshots are rejected in V2 mode. Replay deliberately refuses readiness after `CUTOVER2`, and no runtime command emits that event; the staged code must not be presented as enforcing selectable tiers.

The scaffold has not been proven end to end. In particular, cutover and rollback, full crash recovery, scheduler and broker integration, authorization fencing, deployment procedure and operation against a real Linux Slurm instance remain to be reviewed and verified together. No active ledger should be rewritten and no running allocation interrupted to perform cutover. The user's decision about old records must be applied through a separately reviewed migration, not assumed by the scaffold's legacy import.

A Mac syntax check succeeded for the staged controller, scheduler, arithmetic and marker parser. A complete Mac build is unsuitable as release evidence: it stopped at `full_version.map`. On u20, a low-priority isolated `make -j2 -C src` completed for the source tree and patch corresponding to project commit `d2e403935737e1cf60ba0b5cfd184c85faadcf68`. The resulting candidate `slurmctld` SHA-256 was `b5bb5f6b46b437fd7d33a75daac7c46e18eef9f35bc227cbea68508ea041a823`. The temporary build is `/tmp/time-selectable-build-d2e4039` on u20; its archive was a reconstructed source tree rather than the pinned archive directly checked by the release builder. Required production plugins, reproducible provenance and runtime behavior were not verified by this compile, and nothing was installed or restarted.
