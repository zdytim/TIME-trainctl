# Staged broker monthly grant outbox

`u20-broker-monthly-grant.patch` follows the u20 runtime-targeted idempotency and controller-read patches. With the grant feature explicitly enabled, it creates idempotent per-user monthly applications, records the admin decision and an immutable grant intent in one SQLite transaction, then calls the controller outside that transaction. The application becomes APPROVED only after a controller OK and a second transaction. Any unconfirmed result keeps the original target, amount, month, approval actor and application ID in GRANT_PENDING; an administrator-only `grant-reconcile` endpoint repeats precisely those fields. Controller-side globally bound grant IDs prevent a repeat from adding a second grant. The decision and confirmation are audited, and confirmation notifies the applicant.

The feature defaults off. No grant is automatically sent by this patch while disabled. Legacy non-monthly application handling remains separate. This is untested staged code, not deployment: migration, controller restart, application authorization, month-boundary decisions, crash points and outbox repair require review and behavior validation. A controller OK followed by a failed database commit remains pending and must be reconciled with the same ID. No active accounting or API behavior has changed. CLI/MCP monthly mutation is still withheld.
