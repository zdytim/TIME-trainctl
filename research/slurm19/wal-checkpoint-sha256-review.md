# WAL content checksum candidate

The candidate appends a SHA-256 of the exact WAL bytes to each sequence checkpoint. Startup replays the WAL, recomputes its digest under the existing file lock, and rejects a missing, old-format, malformed, sequence-mismatched or digest-mismatched checkpoint. Each append extends a copied SHA-256 context and stores the digest after the WAL fsync; an interrupted write between the two remains fail-closed. The fresh-ledger initializer creates the new format. Existing old-format checkpoints are deliberately rejected; migration requires a separate, reviewed process and must not silently reset usage.

This detects accidental or unauthorized modification of WAL contents when the checkpoint remains independently intact, including changes that preserve the event sequence. It does not authenticate either file, stop a same-UID writer from changing both, detect coordinated restoration of an older matching WAL/checkpoint pair, or establish power-loss behavior. An independent trusted anchor is still required for the stronger recovery guarantee. The change adds OpenSSL `libcrypto` as a controller build/runtime dependency; its version and library resolution must be recorded for a release. This source candidate is not installed or enabled; it must be rebuilt and validated in isolation before use.

On 2026-10-30 committed candidate `aa21a65` built successfully on u20 in a separate user-owned release-layout build, controller SHA-256 `cb66f955aca7022c1216a4ed4edf1660bf5c5959b94981d8875857db71b8b999`. In networkless containers with private state and fake GPUs, a healthy ledger admitted a job and accounted usage; a same-sequence modification changing a completed event's UID caused the socket to report unavailable and left the GPU request unallocated. A control using the previous `ae47c8f` controller and old checkpoint format accepted the same syntactically valid modified WAL, supporting that the new digest caused the different outcome. An old-format checkpoint was rejected without allocating the pending GPU job. Additional isolated checks covered fresh initialization, a running job across abrupt controller restart, grant idempotency across clean restart, and an exhausted ordinary user's queued job starting and completing after a broker grant. The first image attempts lacked MUNGE and then hwloc runtime libraries and were not counted as test results. Mixed queues remained conservatively paused during ledger failure, and the displayed reason could be stale. None of these checks establishes coordinated rollback detection, a trusted external anchor, live driver/device isolation, production migration, physical power-loss behavior or full plugin/ABI compatibility. The monthly gate remains disabled.
