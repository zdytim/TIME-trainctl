# Staged terminal consent host

`time_mcp_confirm.py` starts the staged MCP server with a private socketpair and presents the exact normalized submit or cancel request on its controlling terminal, rendered as escaped ASCII JSON. The operator must enter `YES` within 60 seconds for a nonce- and digest-bound response. The launcher verifies the action hash and only supports job submit or a specific job cancellation. MCP protocol stdin/stdout are inherited unchanged; the consent channel is separate. Without a controlling terminal it removes any inherited consent-FD setting and starts the MCP in read-only mode. The installer candidate now includes a separate `time-mcp-confirm` launcher and tracks it for rollback.

This offers a concrete local human-consent host for terminal-driven MCP clients; GUI or detached hosts without a controlling terminal remain read-only. Same-user operating system processes or a malicious terminal can still impersonate interaction; the Unix account remains the security boundary. No behavior tests, consent prompts, training jobs, installer execution, or production deployment were performed. Monthly grants and other administrative MCP mutations remain disabled.
