# Month conversion defect found in isolation

The isolated controller built from `2f57b32` reported month `202710` for timestamp `1793342846` (2026-10-30 UTC), while Beijing time was still October 2026. This was a real controller socket response, not a passing quota test. The civil-date inverse increments the year for March through December instead of January and February: `y += (mp < 10)`. This can assign accounting and grants to the wrong year and compute incorrect month boundaries. The staged correction uses `mp >= 10`, matching the transformed March-based calendar representation. The existing production controller was not changed.

The change must be compiled and checked at year and month boundaries, including Shanghai midnight, leap years and an actual isolated controller snapshot before any deployment. A matching source fix alone does not prove accounting, scheduling or recovery. No quota gate has been activated.

After the user requested tests, `test_calendar_source.py` extracted the actual calendar functions from the reconstructed sources and compared every monthly boundary and adjacent second in 1970–2100 with Python's UTC+08:00 dates. The old `2f57b32` source failed (January 1970 was reported as January 1969); the corrected `08b076a` source passed. The corrected controller was built on u20, SHA-256 `d111812807db535ce6fd02bb70152afd4f2cd6d95c53141f1db8c683d498962d`. In a separate networkless, no-host-mount, no-GPU container with a fresh ephemeral MUNGE key and ledger, the corrected controller reported UP and its socket returned month `202610` for its 2026-10-30 timestamp. The query helper cross-checks the returned timestamp against UTC+08:00. This proves neither real GPU isolation nor queue/accounting correctness.

The first smoke script incorrectly interpreted `scontrol ping` exit status as a healthy controller; its output actually said DOWN. That result was rejected. Revision `6cf1838` requires explicit `is UP` and a live controller process; the isolated hostname was explicitly mapped to loopback. The final result above used that corrected check. No existing service was restarted and the monthly gate remains disabled on u20.
