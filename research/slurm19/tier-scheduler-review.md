# Staged monthly tier scheduler integration

`tier-scheduler-integration.patch` applies after `89d30b5` and the existing tier snapshot patch. It takes one locked monthly usage snapshot per queue sort, stores each entry's tier for the duration of sorting, and ranks debug before important before normal before exhausted, then uses the original job priority and submit-time tie-breakers. Existing Slurm preemption, reservation and partition precedence remain ahead of the monthly tiers. CPU-only entries use the neutral normal tier; this defines their relationship to GPU jobs rather than conditionally comparing only GPU pairs, which could make the ordering non-transitive. Failed or unavailable snapshots reset every queue entry to the neutral tier; final GPU admission remains fail-closed independently.

The common `sort_job_queue` is called by ordinary scheduling and both builtin and backfill schedulers. With the gate enabled, the main scheduler's FIFO shortcut is disabled so it also builds and sorts a queue. This is source-level integration only: selected ordering precedence and CPU interaction require review, and backfill reservation behavior, multiple partitions, concurrent ledger changes, failure and restart behavior have not been validated. The stored tier is a point-in-time ordering hint, not a GPU reservation or replacement for final admission. Changes to the queue structure require rebuilding matching components.

Do not enable the controller based on this patch. The candidate still lacks rollback protection against a complete old ledger prefix, an authenticated grant route and runtime/ABI validation. No tests or jobs have been run.
